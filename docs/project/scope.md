# Initial Project Scope

## Purpose of This Document

This document preserves the original purpose of AI Mastery Roadmap as it was defined when the repository was created.

Unlike the roadmap, which is expected to evolve as the learner gains experience and the learning path is refined, this scope should remain largely stable. Its purpose is to make it possible, years later, to understand what this journey was originally created to achieve and why the repository exists.

Changes to this document should therefore be rare and limited to correcting a genuine misrepresentation of the original scope or recording an explicitly approved change to the project's fundamental purpose.

## Original Goal

The goal of this journey is not merely to learn Python.

The long-term objective is to develop from a Fachinformatiker background toward strong AI engineering capability and, ultimately, toward research-oriented work in artificial intelligence.

Python is the first major tool in that journey, not the destination.

The repository exists to turn that long-term objective into a structured, visible, project-based learning path rather than a conventional sequence of isolated lessons.

## What the Journey Is Intended to Build

The learning journey is intended to develop progressively stronger capability across the areas required for serious AI engineering and later research practice.

The original direction includes:

- Python programming foundations;
- Git and practical development workflow;
- Linux fundamentals;
- software engineering;
- professional Python development;
- machine learning fundamentals;
- implementing important machine-learning ideas from first principles where useful;
- deep learning;
- neural networks and modern training tooling;
- attention and transformer architectures;
- LLM engineering topics such as fine-tuning, LoRA, retrieval, embeddings, and quantization;
- reading technical papers;
- reproducing research results at an appropriate scale;
- designing and evaluating experiments;
- eventually developing the ability to investigate original questions.

The precise ordering, depth, technologies, and individual missions may change over time. Those details belong to the roadmap and level curricula. The underlying destination does not: build the practical and theoretical depth needed to move from programming foundations toward AI engineering and research.

## Learning Model

The project was deliberately conceived as a learning journey built around visible progress and concrete work rather than a traditional chapter-based course.

The intended model uses:

- levels to represent major stages of development;
- missions as focused learning units;
- real projects as evidence of applied capability;
- larger boss challenges to combine previously learned skills;
- review work when later evidence exposes gaps;
- reflection to record what was learned, what was difficult, and what needs further work.

The repository should avoid artificial filler work. Learning tasks should have a concrete purpose, and completed projects should, where practical, be meaningful enough to form part of a long-term portfolio.

## Learner Responsibility and AI Assistance

A central objective is genuine capability rather than the appearance of completion.

During actual learning missions, the learner is expected to write the core solution and understand the important concepts and decisions involved.

AI may act as tutor, reviewer, coach, debugging partner, and source of progressively stronger hints. It may explain concepts, answer questions, review learner-written work, identify mistakes, suggest tests, and challenge decisions.

The learning journey should not normally be completed by having an AI silently generate the core solution in place of the learner.

Repository setup, documentation, curriculum design, templates, progress infrastructure, and similar framework work may be created with direct AI assistance because they are infrastructure for the learning process rather than the learning solution itself.

## Persistent and Agent-Independent State

The repository is intended to be more than a storage location for code.

It should act as the persistent state of the learning journey so that progress does not depend on the memory of one chat, one tutor, one agent, or one AI model.

Over time, the repository should make it possible to determine from durable evidence:

- which missions have been completed;
- which skills have been demonstrated;
- where difficulties or recurring mistakes occurred;
- which topics need review;
- which projects have been built;
- which learning level is active;
- which larger challenges remain open;
- what the next appropriate learning step is.

A future tutor should be able to continue the journey by reading the repository rather than relying on undocumented conversational history.

## Public Learning Journey and Portfolio

The repository was also conceived as a public record of genuine development over time.

Its value comes from showing increasing technical depth, meaningful projects, reflection, revisions, and demonstrated understanding rather than presenting an artificially perfect history.

The long-term result should function simultaneously as:

- a learning platform for the learner;
- a persistent progress record;
- a portfolio of increasingly advanced work;
- a durable handoff point for future human or AI tutors.

## Relationship to the Roadmap

This document defines the stable destination and original reason for the project.

`../learning/roadmap.md` defines the current planned route toward that destination and may evolve as the learner, available technology, and teaching approach develop.

Level curricula, missions, projects, assessments, and supporting resources are implementation details of that route. They may change without changing this initial scope.

The distinction is intentional:

- **Initial scope:** why the journey exists and what it is fundamentally trying to achieve.
- **Roadmap:** the current plan for reaching that goal.
- **Progress state:** where the learner actually is now.
